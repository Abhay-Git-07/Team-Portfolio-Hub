# 🌐 Team Portfolio Hub

A collaborative team portfolio website developed as a college mini project.

## 📌 About the Project

**Team Portfolio Hub** is a portfolio website created to showcase our team members, their skills, projects, achievements, and learning journey in one place.

The project is being developed collaboratively using **Git and GitHub**, with each team member contributing through separate branches and Pull Requests.

Our goal is not only to build a portfolio website but also to gain practical experience in **web development, version control, teamwork, and collaborative software development**.

## 🎯 Project Goals

The main goals of this project are:

* Create a simple, professional, and responsive team portfolio website
* Introduce all team members and their individual roles
* Showcase the skills and technologies learned by each member
* Display projects developed by the team
* Highlight individual achievements and learning journeys
* Provide links to relevant professional and social profiles
* Practice HTML and CSS through a real-world project
* Learn and practice Git and GitHub
* Understand branches, commits, Pull Requests, and code reviews
* Develop the project collaboratively as a team
* Improve the website gradually as we learn new technologies

## 🔀 Git & GitHub Workflow

We are following a **feature-branch workflow** to keep development organized and collaborative.

```text
                    main
                      │
             ┌────────┼────────┐
             ↓        ↓        ↓
          Feature   Feature   Feature
          Branch    Branch    Branch
             │        │        │
          Changes   Changes   Changes
             │        │        │
             └────────┼────────┘
                      ↓
               Pull Request
                      ↓
                   Review
                      ↓
              Approved Changes
                      ↓
                    main
```

### Development Process

1. Create a separate branch for a specific task or feature.
2. Make changes only on that branch.
3. Test the changes locally.
4. Commit the changes with a meaningful commit message.
5. Push the branch to GitHub.
6. Create a Pull Request targeting `main`.
7. The Project Lead reviews the Pull Request.
8. Changes are requested if improvements are needed.
9. Once approved, the Pull Request is merged into `main`.

> **Direct pushes to the `main` branch are avoided.**

---

## 📋 Contribution Guidelines

Before creating a Pull Request:

* Keep your changes related to the assigned task.
* Write clean and readable HTML/CSS.
* Follow the existing project structure.
* Avoid unnecessarily changing another team member's work.
* Test your changes before creating the Pull Request.
* Use meaningful commit messages.
* Explain what you changed in your Pull Request.
